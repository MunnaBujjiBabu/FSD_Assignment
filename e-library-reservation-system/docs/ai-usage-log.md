## Reflection (1–2 pages)

### Did AI help or hinder understanding?
AI accelerated scaffolding and let me focus on the **architecture and integration** instead of boilerplate. I had to actively read each generated file (Express routes, JWT flow, SQLite calls) to truly understand the request lifecycle from React → Gateway → Service → DB.

### Issues encountered integrating AI output
- Initial `npm install` failed due to local environment permissions (not AI’s fault) — solved by running locally with proper Node/npm setup.
- Cross-service calls (reservation → catalog) needed an internal service key to prevent unauthorized stock changes — added explicitly after review.
- JWT had to be verified at the gateway and forwarded as `x-user-*` headers so each service stays decoupled from auth library.

### What I learned from debugging AI-generated code
- Importance of explicit role checks at each service boundary.
- Why an API gateway pattern is useful: single auth choke-point, simpler service code.
- Trade-off of denormalized snapshots (e.g., `book_title` in reservations) for cross-service simplicity vs. consistency.

### Limitations Observed
- AI assumes “best-case” environment; local tooling/permission issues still need human handling.
- Generated code can over-engineer; trimmed unnecessary helpers during review.
- AI cannot validate runtime behavior — we still must run, click, and verify.
